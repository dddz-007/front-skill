# 单点修改流程

适用于用户指定一个文件、一个代码块、一个样式区域，或强调“只做这个修改”的任务。

## 一、锁定范围

1. 明确唯一允许修改的文件、区域和行为。
2. 阅读用户指定的参考实现以及目标代码的直接上下文。
3. 逐项比对参考与目标，只提取用户要求保持一致的计算、结构、样式或交互。
4. 只做完成目标所必需的最小修改。
5. 相邻问题若不阻止本次代码编译或运行，不顺手修复；若确实阻塞，先说明再扩大范围。

## 二、禁止附带变化

未经明确要求，不得修改：

- 组件对外 API、Props/Inputs、事件、回调和返回值；
- 默认值、状态初始化、监听器、生命周期和副作用；
- 路由、请求、Store、缓存、权限、埋点和数据结构；
- 组件库配置、主题、挂载方式和交互行为；
- 无关文案、注释、图标、样式和其他文件。

不得启用或禁用注释代码，不做广泛格式化，不借机重构。

## 三、安全编辑

- 使用当前平台提供的局部补丁或精确编辑工具，并以准确上下文定位修改。
- 补丁匹配失败时，重新读取目标原文；禁止改用整文件正则替换或脚本覆盖。
- 含中文或其他非 ASCII 字符时，不经过系统默认编码读写。
- 文件出现非法 UTF-8、乱码或异常 BOM 时，立即停止，从可信版本恢复后再重新应用最小补丁。

## 四、验证

1. 查看该文件的聚焦 Diff。
2. 确认只有允许区域发生变化。
3. 执行 `git diff --check`。
4. 对目标文件执行适用的解析、Lint、类型或编译检查。
5. 可见变更只验证受影响的界面或交互。

最终说明是否修改了任何其他文件或行为；答案应明确且可核对。
